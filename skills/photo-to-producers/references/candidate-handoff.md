# Candidate handoff

Use after visual inventory for useful concrete missing-product leads, or when
the user explicitly requests product research candidates. This is an editorial lead, not an approved product, producer
proposal, ownership claim or assertion that Chisan has no stored record.

## Decide what merits a candidate

A useful product candidate has a concrete readable name or distinguishing
variant/format, a source occurrence, a plausible attribution and a reason worth
checking. Reasons include an explicitly requested product, a distinct named
offering, or an observed variant not resolved among the checked products.
Do not invent a quality score, demand forecast or marketing claim. Generic
ingredients, restaurant dishes and illegible fragments remain observations.
An explicitly named packaged drink on a drinks list may be a research lead;
the menu itself still does not establish a catalog product ID.

Before proposing a duplicate, inspect the selected producer's visible products
and use useful name alternatives when necessary. Compare format/variant only
where recorded. Search limitations, hidden products and failed reads stay
explicit. Say **not found among the visible records checked**, not **absent from
Chisan**. A failed search alone does not create a candidate; a concrete observed
product can remain a lead with duplicate checking pending.

Repeated appearances of the same producer/product yield one candidate with all
useful source references. Preserve genuinely different variants. A producer-only
match never confirms the exact product. A generic catalog name may be a possible
duplicate, not a justification to create another product automatically.

## Keep one small record per lead

| Field | What to retain |
| --- | --- |
| Product | Literal readable name; explicit format/variant if any. Preserve source language. |
| Producer | Returned country/producer ID and profile link if resolved; otherwise the observed name and unresolved attribution. Never mint an ID. |
| Evidence | Image/page/item reference and the short supporting reading. Separate label facts, owner statements, catalog facts and independently verified public sources. |
| Search scope | Which producer/products and relevant name alternatives were checked, date/revision if available, and any visibility or access limitation. |
| Reason | The concrete reason this is worth investigating for the user's request. |
| Next question | One actionable blocker: confirm manufacturer, find the official product page, distinguish an existing variant, or verify the format. |
| Destination | Prepared in this answer, an actual saved file, or a confirmed receipt from an authorized submission tool. Do not invent a queue or receipt. |

Prices, currency, purchase URL and image rights are optional at discovery. Missing
fields stay missing; no guessed shop URL or price borrowed from another size.
A retailer price is attributed to that retailer, not to the producer. Before
publishing commercial details, use current official product evidence for the
exact variant and the applicable editorial/media review.

## Route and save honestly

The public plugin has no candidate-write operation. Include **Potential products
to review** in the answer and state that these are prepared here, not saved in
Chisan. A requested export may use the host's existing file capability. Do not
ask the user to connect an account or imply a background submission exists.

In an explicitly authorized Chisan editorial workspace, follow its local rules:

- A product belonging to an existing producer goes through the producer-content
  research workflow, after checking the full stored package for duplicates.
  Public visibility does not establish stored absence.
- An unresolved or new productive identity goes through producer admission
  research before any product package can be created. Retain the product clue
  with that lead instead of registering a brand as a producer.
- User photographs and private context stay in the conversation or authorized
  private working material. A tracked/public research note needs independently
  verified public sources; do not copy private photos, device positions, account
  details or private attachment URLs into repository notes or public links.

Only report a save after a successful file write or acknowledged tool operation,
with the actual destination. Reuse the existing note for the same lead instead
of appending duplicates. Review, acceptance and publication remain later stages.
